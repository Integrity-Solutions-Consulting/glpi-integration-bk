INTEGRACION AUTOMATICA TMR / INVENTARIO -> GLPI

ESTADO

La automatizacion esta implementada en el servicio `automatizacion` de
compose.yaml. Ejecuta un ciclo inmediatamente al iniciar y despues cada 5
minutos por defecto. En cada ciclo sincroniza:

- usuarios TMR nuevos;
- proyectos TMR;
- perfiles GLPI segun los roles TMR;
- equipos del inventario;
- detalles de equipos, catalogos, estados, ubicaciones y caracteristicas.

El intervalo puede cambiarse con `SYNC_INTERVAL_MINUTES`. Para pruebas,
`SYNC_INTERVAL_SECONDS` tiene prioridad; actualmente esta configurado en 5
segundos. Antes de produccion debe eliminarse o dejarse vacio para volver a
5 minutos. Los limites de escritura son `SYNC_MAX_WRITES`,
`EQUIPMENT_MAX_WRITES` y `EQUIPMENT_DETAIL_MAX_WRITES`.

La limpieza de categorias no se ejecuta automaticamente porque puede eliminar
activos de GLPI. Esa operacion continua siendo manual.

El archivo `data/last-automatic-sync.json` confirma el ultimo ciclo. Su campo
`status` debe ser `OK`; si es `ERROR`, revisar `error` y los logs del contenedor.

REQUISITOS ANTES DE ACTIVAR

1. Copiar `.env.example` a `.env` y completar las credenciales de TMR,
   inventario y GLPI. No publicar `.env`.
2. Habilitar la API REST legacy de GLPI.
3. Autorizar en el cliente legacy la IP de salida del servidor o contenedor.
4. Configurar `GLPI_LEGACY_APP_TOKEN` si el cliente legacy lo exige.
5. Dar a la cuenta de integracion permisos para leer y crear usuarios,
   proyectos y activos, asignar perfiles y acceder a la entidad raiz.
6. Mantener `SYNC_DATA_DIR` en un volumen persistente. El diario evita
   duplicados entre ciclos y debe conservarse privado.

VALIDACION RECOMENDADA

Primero ejecutar una revision sin escritura:

    docker compose run --rm --build revision

Luego hacer una primera alta controlada:

    docker compose run --rm --build transferencia node src/transfer.mjs --apply --max=1

Despues verificar el usuario y sus permisos en GLPI. Para probar equipos de
forma controlada se pueden usar los comandos de `TRANSFERENCIA.md`.

ACTIVACION CONTINUA

En Dokploy desplegar la aplicacion desde este repositorio y reconstruir la
imagen. El `Dockerfile` ya inicia `src/auto-sync.mjs`; si se usa Docker Compose,
desplegar el servicio `automatizacion`, sin dominio ni puertos.
Con Docker local:

    docker compose up -d --build automatizacion

Cuando TMR o el inventario tengan informacion nueva, aparecera en GLPI en el
siguiente ciclo, como maximo 5 minutos despues. No es una notificacion por
evento instantanea.

LIMITACIONES

- Las cuentas GLPI existentes no se adoptan si no existe una vinculacion segura;
  quedan para revision.
- Lideres o perfiles sin equivalencia verificada quedan para revision humana.
- No se copian contrasenas de TMR ni se habilita inicio de sesion compartido.
- La automatizacion no elimina activos ni modifica cuentas no vinculadas.
- Los tickets de GLPI no se crean a partir de cualquier campo de TMR; la
  sincronizacion actual cubre identidades, proyectos, perfiles y activos.

Para detalles de altas, recuperacion y errores consultar TRANSFERENCIA.md y
VALIDACION-GLPI.md.
